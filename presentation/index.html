Bales

A cost-aware gateway for mixed LLM traffic.

Bales sees a prefix before the engine does. It decides whether a duplicate request should wait for an in-flight prefill or move to a spare GPU, prices the cache hit in milliseconds, and keeps stream and batch traffic on separate virtual deadlines.

prefix coalescing calibrated prefill cost virtual deadlines

Arrow keys navigate and T switches the theme. Every number comes from the checked-in evidence ledger.

engine-agnostic · OpenAI-compatible · Go 1.27
01 · The problem

Duplicate prefill in a cold burst

A cold burst arrives before the first prefill finishes. A router with speculative indexing records the cache entry at dispatch, so every follower believes the prefix is ready and piles onto the same replica.

  • The engine schedules the duplicates into the same prefill batch and recomputes the same 2k tokens.
  • Follower TTFT grows with the number of copies, while useful work stays constant.
  • The burst itself gains nothing from prefix caching.

02 · Why it costs

    
Prefill cost and cache value

    

      

        
Prompt tokens run through every transformer layer before the first output token appears. Attention pairs grow with the product of new tokens and cached context, so a long prefix is worth more than a short one to the request that reuses it.

        
Decode is a different regime: one token per step per request, limited by memory bandwidth. A scheduler that treats both phases as one latency number makes the wrong trade.

        

          Identity
          For a cached prefix of length L, the avoided work is the prefill cost of L. The value of a hit is superlinear in L.

04 · Thesis

    
A missing gateway primitive

    
Engine-agnostic in-flight prefix coalescing with a load-aware hold rule.

    

      
01
Coalesce
Wait for a leader only when the saved prefill beats the wait. Otherwise spill to spare capacity.

      
02
Price
Fit the prefill model per deployment. Use the exact saving in routing and hold decisions.

      
03
Bound
Give stream and batch traffic static virtual deadlines and cap admitted work.

    3. 
          
  3. Decide hold or spill in milliseconds; register the leader before dispatch.
    4. 
          
  4. Route by earliest completion time under KV and ITL constraints.
    5.

Model state stays in the replicas. The gateway stores only scheduling state, so a restart loses no weights or KV blocks.

10 · Affinity

    
Affinity has a threshold

    

      

        
recoverable = λ · saving(prefix)

        

        

        
REPLICATE3 replicas

        
threshold

        
Spread when recoverable work is small, pin when one replica can carry the group, replicate when the group needs k replicas.

      

      

        
what the simulation showed

        
Single-pin affinity was 2 to 3 times worse than round robin on hot traces. The gate prescribes replicate for those traces, which the prototype has not yet implemented as a routing policy.

        
The gate is a first-class part of the design.
